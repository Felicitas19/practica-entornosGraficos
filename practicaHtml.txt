1. ¿Qué es HTML, cuándo fue creado, cuáles fueron las distintas versiones y cuál es la última?
HTML (HyperText Markup Language) es un lenguaje de marcas de hipertexto utilizado para definir la estructura básica y el contenido de una página web (textos, imágenes, videos, etc.). No es un lenguaje de programación porque no posee variables ni funciones aritméticas, sino que emplea etiquetas predefinidas para estructurar la información.
Fue desarrollado originalmente por Tim Berners-Lee y se popularizó con el navegador Mosaic en 1993.
Durante los años 90 el HTML proliferó y se fue desarrollando de diferentes maneras a medida que la Web crecía.
La revisión más importante y última versión estandarizada mencionada en el documento es HTML5.

2. ¿Cuáles son los principios básicos que el W3C recomienda seguir para la creación de documentos con HTML? 
Según el W3C (World Wide Web Consortium), los principios básicos son la interoperabilidad y el acceso universal. El HTML ha sido desarrollado con la premisa de que "cualquier tipo de dispositivo debería ser capaz de usar la información de la Web", desde PCs con distintas resoluciones hasta teléfonos móviles y dispositivos de voz. Además, el W3C recomienda usar hojas de estilo (CSS) para separar la estructura (HTML) de la presentación visual (colores, fuentes), de modo que los documentos se rendericen correctamente en distintas plataformas.

3. En las Especificaciones de HTML, ¿cuándo un elemento o atributo se considera desaprobado? ¿Y obsoleto?
Un elemento o atributo se considera obsoleto cuando el W3C decide que ya no debe usarse en el futuro, generalmente porque han surgido mecanismos más potentes para reemplazarlos (como el uso de CSS en lugar de etiquetas de diseño directo como <font>).
A lo largo de la especificación, los elementos y atributos que están en proceso de ser retirados se marcan como "desaprobados" para advertir a los desarrolladores que dejen de utilizarlos, ya que eventualmente quedarán obsoletos.

4. ¿Qué es el DTD y cuáles son los posibles DTDs contemplados en la especificación de HTML 4.01?
DTD significa Document Type Declaration (Declaración del Tipo de Documento). Es una sección que se ubica en la primera línea del archivo (antes de <html>) y sirve para indicarle al navegador qué especificación o versión de HTML se está utilizando para que pueda interpretarlo correctamente.

5. ¿Qué son los metadatos y cómo se especifican en HTML? 
La información destinada a configurar el documento y a darle directivas al navegador, es a lo que llamamos metadatos, ya que es "información oculta al usuario"— se especifica ubicándola dentro de la cabecera del documento, utilizando la etiqueta <HEAD>. Todo lo que se coloca allí no se ve directamente en la página, a excepción del <TITLE> que aparece en la pestaña.

Ejercitación 2:
2.a) <!-- Código controlado el día 12/08/2009 -->
Es un comentario. El navegador lo ignora completamente y no se visualiza en la página.
Puede ir en cualquier parte del documento (<head> o <body>).
No posee atributos.
2.b) <div id="bloquel">Contenido del bloquel </div>
Sección en <body>.
Crea un contenedor de bloque genérico (una "caja") para agrupar contenido.
Elementos y etiquetas: Elemento div (etiquetas de apertura <div> y cierre </div>).
Atributos: id (valor: "bloquel"). Es opcional, sirve para identificar este bloque de forma única (por ejemplo, para aplicarle CSS o JavaScript).
2.c) <img src="" alt="lugar imagen" id="im1" name="iml" width="32" height="32" longdesc="detalles.htm" />
Sección: <body>.
Efecto: Inserta una imagen en la página (es un elemento vacío, no tiene etiqueta de cierre).
Atributos obligatorios: src (indica la ruta de la imagen, acá está vacío) y alt (texto alternativo si la imagen no carga).
Atributos opcionales usados: id (identificador), name (nombre), width y height (ancho y alto en píxeles), longdesc (enlace a una descripción larga).
2.d) Etiquetas <meta>
Sección: <head>.
Efecto: Aportan metadatos ocultos al usuario. El primero define palabras clave (keywords) para los motores de búsqueda. El segundo fuerza la expiración del caché del navegador para una fecha específica.
Atributos: name (tipo de metadato), lang (idioma), content (el valor del metadato, obligatorio cuando se usa name o http-equiv), y http-equiv (simula un encabezado HTTP).
2.e) <a href="http://..." type="text/html" hreflang="es" charset="utf-8" rel="help">Resumen HTML </a>
Sección: <body>.
Efecto: Crea un ancla o hipervínculo hacia otra página externa.
Atributos obligatorios: href (valor: la URL de destino).
Atributos opcionales usados: type (tipo de documento destino), hreflang (idioma del destino), charset (codificación), rel (relación con el destino, en este caso "help").
2.f) Etiqueta <table> y su estructura
Sección: <body>.
Efecto: Dibuja una tabla de datos de 200px de ancho con un título, una fila de encabezados (A, B, C) y dos filas de datos (1°, 2°).
Elementos:
<table>: Contenedor principal. Atributos opcionales: width="200", summary="Datos...".
<caption>: Título de la tabla. Atributo opcional: align="top".
<tr>: Define cada fila (Table Row).
<th>: Define celdas de encabezado (negrita y centradas por defecto). Atributo opcional: scope="col" o scope="row" (indica si encabeza columna o fila).
<td>: Define las celdas de datos normales (Table Data). Contienen &nbsp; (espacios en blanco) para que no queden vacías visualmente.

3.a) Diferencias en los enlaces (etiqueta <a>)
Primer enlace: Es un hipervínculo clásico. Si hacés clic, la página de Google se va a abrir en la misma pestaña en la que estás navegando, reemplazando tu página actual.
Segundo enlace (target="_blank"): Al agregar este atributo, el navegador es forzado a abrir el enlace de Google en una nueva pestaña o ventana, manteniendo tu página original abierta.
type, hreflang, charset, rel: Visualmente será igual a un enlace normal, pero contiene atributos avanzados (metadatos) que le indican al navegador y a los motores de búsqueda que el archivo de destino es un HTML en español (es), con codificación UTF-8 y que es un enlace de ayuda (rel="help").
Cuarto enlace (href="#"): Se ve como un enlace, pero el numeral o almohadilla (#) indica que es un enlace vacío. Al hacer clic, no te lleva a otra página, sino que hace que la vista salte automáticamente al tope de tu página actual.
Quinto y sexto enlace (href="#arriba" y name="arriba"): Trabajan en conjunto. El último segmento (name="arriba" id="arriba") define un "ancla" invisible en algún lugar del código. El enlace anterior (href="#arriba") es el botón que te permite saltar (hacer scroll automático) exactamente hacia donde está ubicada esa ancla dentro del mismo documento.
3.b) Diferencias entre imágenes y enlaces (<img> y <a>)
Segmento 1: La etiqueta del enlace (<a>...</a>) solo envuelve al texto "Click aquí". La imagen está suelta al lado. Si hacés clic en la imagen, no pasa nada.
Segmento 2: El enlace envuelve solamente a la imagen 
(<a href...><img.../></a>). Esto hace que la foto se convierta en un botón clickeable. El texto "Click aquí" quedó afuera del enlace, por lo que es solo texto plano.
Segmento 3: El enlace envuelve tanto a la imagen como al texto. Forman un único botón gigante; hagas clic en la foto o en la palabra, ambas te llevan al destino.
Segmento 4: Acá hay dos enlaces independientes uno al lado del otro (hay dos aperturas <a> y dos cierres </a>). La imagen es un enlace y el texto es otro enlace separado, aunque ambos apunten a Google.

3.c) Diferencias en las Listas (<ul>, <ol> y simulaciones) 
Primer segmento (<ul>): Es una lista desordenada (Unordered List). Visualmente, el navegador muestra los ítems con viñetas o puntitos.
Segundo segmento (<ol>): Es una lista ordenada (Ordered List). El navegador numera los ítems automáticamente de forma secuencial (1., 2., 3.).
Tercer segmento: Visualmente se verá igual que el caso anterior (1., 2., 3.), pero estructuralmente está "roto": son dos listas <ol> separadas. Para forzar que la segunda lista continúe la numeración, usa los atributos value="2" y value="3" directamente en los <li>.
Cuarto segmento (<blockquote>): No es una lista real. Usa una etiqueta de cita en bloque (<blockquote>) para empujar el texto (sangría), y luego dibuja la lista escribiendo los números a mano ("1. xxx") separando los renglones con <br>. A simple vista parece una lista, pero a nivel de código (y para accesibilidad) es un error grave.
3.d) Diferencias en los Encabezados de Tablas (<th> vs <td> forzados) 
Primer segmento (La forma correcta): Para la primera fila usa la etiqueta semántica <th> (Table Header). El navegador sabe automáticamente que es un encabezado y, por defecto, pone el texto en negrita y lo centra.
Segundo segmento (La forma incorrecta/sucia): Para los títulos usa celdas de datos comunes <td>. Para intentar imitar al encabezado, le inyecta etiquetas extra adentro: un <div align="center"> para centrarlo y un <strong> para engrosar la letra. Es mala práctica porque ensucia el código.
3.e) Títulos de Tablas (<caption> vs colspan)
Primer segmento: Usa la etiqueta <caption>. Esta es la forma semánticamente correcta de ponerle un título a una tabla. El texto queda adherido a la tabla pero "por fuera" de la cuadrícula.
Segundo segmento: Elimina el <caption> y lo reemplaza creando una fila extra adentro de la tabla. Usa el atributo colspan="3" para fusionar las tres columnas de esa fila en una sola celda gigante, y ahí adentro escribe "Título" centrado.
3.f) Fusión de celdas verticales (rowspan)
Primer segmento: Utiliza el atributo rowspan="2". Esto fusiona una celda verticalmente para que ocupe el espacio de dos filas, lo cual es la forma correcta de estructurarlo.
Segundo segmento: Intenta simular el diseño usando un colspan="2" horizontal en otra fila. Aunque pueda tratar de imitar visualmente el espacio, estructuralmente es incorrecto porque no está combinando celdas hacia abajo.
3.g) Espaciado de Tablas (cellpadding y cellspacing)
Primer segmento: Dibuja una tabla estándar. Por defecto, los navegadores dejan un pequeño espacio entre los bordes de las celdas.
Segundo segmento: Agrega los atributos cellpadding="0" (espacio entre el borde de la celda y el contenido) y cellspacing="0" (espacio entre las celdas mismas). Esto hace que los bordes de la tabla se "peguen" o colapsen, dándole un aspecto mucho más compacto.
3.h) Diferencias en los Formularios (<form>)
Aquí hay 3 formularios distintos que ilustran cómo se envían los datos:
Primer formulario: Usa el método post (los datos viajan ocultos) y los envía a procesar.php. Usa la etiqueta <fieldset> para agrupar visualmente los campos, pero nota que el botón de "Enviar" quedó fuera de la etiqueta de cierre </fieldset>.
Segundo formulario: Usa el método get (los datos viajan a la vista por la URL) y no tiene un archivo de destino (action=""). A diferencia del anterior, este envuelve los textos en etiquetas <label>, lo que es una excelente práctica de accesibilidad.
Tercer formulario: Su acción es un mailto:xx@xx.com, es decir, intenta abrir el cliente de correo del usuario para enviar los datos por email. ¡Pero ojo con el botón! Aunque dice "Enviar", es un <input type="reset">, por lo que al hacerle clic no va a enviar nada, sino que va a borrar todo lo escrito en el formulario.
3.i) Botones (<button> vs <input type="button">)
Primer segmento (<button>): Esta etiqueta permite incluir contenido enriquecido adentro. En este caso, el botón tiene adentro una imagen, un salto de línea y un texto en negrita.
Segundo segmento (<input type="button">): Es la forma clásica de hacer botones. Solo admite que le pongas texto plano a través de su atributo value="CLICK AQUÍ". No puedes ponerle una imagen dentro directamente.
3.j) Agrupación de Radio Buttons (<input type="radio">)
Primer segmento: Es la forma correcta. Ambos botones de radio tienen exactamente el mismo atributo name="opcion". Esto le dice al navegador que pertenecen al mismo grupo, por lo tanto, si seleccionas uno, el otro se desmarca automáticamente.
Segundo segmento: Es la forma incorrecta. Tienen nombres diferentes (name="opcion1" y name="opcion2"). Esto rompe el comportamiento del radio button, permitiendo al usuario seleccionar ambos a la vez, lo cual es un error lógico.
3.k) Listas Desplegables (<select>) 
Primer segmento: Es un <select> estándar. El usuario abre la lista y solo puede elegir una única opción.
Segundo segmento: Agrega el atributo multiple="multiple". Esto transforma el menú en un recuadro donde el usuario puede elegir varias opciones al mismo tiempo (generalmente manteniendo apretada la tecla Ctrl en el teclado). Por eso también su nombre cambia a name="lista[]", indicando que enviará un arreglo (array) de datos al servidor en lugar de uno solo.
